# Civic Campaigns RF

Скилл для подготовки и сопровождения личных и коллективных обращений в России, организации общественных кампаний и работы со многими делами одновременно.

Помогает выбрать адресата и процедуру, составить обращение, разобрать ответ, определить следующий шаг и проверить результат. Для общего обзора собирает дела, ветки переписки, сроки и задачи в понятный список.

Версия скилла — **0.6**. Машиночитаемый реестр использует формат **0.4**.

## Для каких задач

| Задача | Что можно получить |
|---|---|
| Личное обращение | Проект заявления или жалобы, адресата, способ подачи, приложения и следующий шаг |
| Коллективное обращение | Общий текст требования, порядок сбора подписей и сопровождения ответа с учётом конкретной процедуры |
| Общественная кампания | Цель, механизм решения, участников, план действий, нагрузку и критерии пересмотра |
| Разбор полученного ответа | Сопоставление ответа с требованиями, нерешённые вопросы и варианты дальнейших действий |
| Несколько дел по разным темам | Общий реестр, приоритеты, ближайшие даты, обзор изменений и подтверждённых результатов |

В пакете есть материалы по ЖКХ и благоустройству, транспорту, экологии, земле и воде, здравоохранению, наследию, цифровым сервисам и взаимодействию с органами власти. Для других тем помощник использует общий порядок работы и проверяет профильные правила.

## Установка в Codex

Попросите встроенный установщик подключить скилл из этого репозитория.

```text
$skill-installer Установи скилл из https://github.com/tayru/civic-campaigns.
SKILL.md находится в корне репозитория. Имя папки скилла — civic-campaigns-rf.
Сохрани справочники, шаблоны и скрипты пакета.
```

Для ручной установки скачайте репозиторий и поместите его содержимое в пользовательскую папку `~/.agents/skills/civic-campaigns-rf/`. Файл `SKILL.md` должен находиться непосредственно в этой папке, рядом с каталогами `references`, `assets`, `agents`, `scripts` и `evals`.

После установки проверьте наличие скилла в списке доступных навыков. Если он ещё не появился, перезапустите Codex. Способы установки и вызова описаны в [официальной документации OpenAI](https://developers.openai.com/codex/skills).

## Первый запрос

В Codex CLI и IDE скилл можно явно вызвать через `$civic-campaigns-rf`. В интерфейсах с выбором навыков выберите «Жалобы, обращения и кампании в РФ».

```text
Используй $civic-campaigns-rf. Помоги подготовить обращение об ошибке
в выданной справке. Ниже исходное заявление и полученный ответ.
Определи, чего не хватает, подготовь текст и следующий шаг.
```

Для начала передайте описание проблемы, желаемый результат и имеющиеся документы. Полезны исходное обращение, подтверждение отправки или регистрации и ответ целиком. Неизвестные реквизиты можно уточнить после первого черновика.

## Примеры запросов

### Коллективное обращение

```text
Используй $civic-campaigns-rf. Жители дома хотят обратиться по поводу
неисправного лифта. Есть журнал остановок и фотографии уведомлений.
Подготовь коллективный текст и объясни, как сохранить подтверждение подачи.
```

### Ответ получен частично

```text
Используй $civic-campaigns-rf. Сравни наше обращение и ответ администрации.
Покажи, на какие требования ответили, какие вопросы остались,
и предложи обоснованный следующий шаг. Документы прилагаю.
```

### Несколько дел одновременно

```text
Используй $civic-campaigns-rf. В приложенных материалах есть личное дело
по исправлению документа, коллективное обращение по освещению
и кампания по сохранению библиотеки. Собери общий обзор.
Покажи ближайшие даты, недостающие сведения и посильный план на два часа.
Сохрани отдельные дела и ветки переписки.
```

### Обновление после новых ответов

```text
Используй $civic-campaigns-rf. Ниже актуальный реестр и два новых ответа.
Определи, к каким делам они относятся, обнови события и следующие действия.
Покажи, что изменилось, и подготовь обновлённый реестр для сохранения.
```

### Общественная кампания

```text
Используй $civic-campaigns-rf. Хотим сохранить районную библиотеку.
Есть ответ администрации и группа из четырёх человек.
Предложи ближайшее требование, варианты действий и план на месяц.
Учти доступные часы и объясни, как проверять продвижение к результату.
```

## Как вести много дел

1. Выберите рабочую папку или документ для актуального реестра и исходных материалов. Укажите помощнику, где они находятся и какой набор дел нужно учитывать.
2. При первом обзоре попросите разделить дела, адресатов и ветки переписки, сохранить устойчивые ID и отметить неизвестные сведения.
3. При новом ответе передавайте текущий реестр вместе с документом. Просите показать изменения, уточнённые даты и следующие действия.
4. Сохраните обновлённую версию. Если помощнику доступна запись в рабочее хранилище, явно поручите обновить конкретный файл и проверьте результат сохранения.
5. При переходе в новый чат передайте актуальный реестр и место хранения документов. Для недельного обзора укажите доступное время и важные для вас результаты.

Одна карточка соответствует делу. Внутри него могут одновременно идти переписка с несколькими адресатами, ожидание ответа и подготовка следующего действия. Обращения отдельных заявителей сохраняют свои требования и сроки даже при общей кампании.

Для обзора можно использовать [шаблон портфеля дел](assets/portfolio-template.md). Он содержит текущий фокус, общий реестр, ближайшие даты, изменения и итоги.

Рабочие документы, контакты и подписи храните в отдельном закрытом пространстве. Для публичного отчёта подготовьте версию с проверенным составом данных.

## Что учитывать в версии 0.6

- Сохранение реестра между чатами зависит от выбранного хранилища и доступных инструментов. В пакете есть инструкции, шаблоны и валидатор. Единый механизм хранения и обновления всех дел пока требует настройки рабочего процесса.
- Машиночитаемый формат ограничен. У дела пока отсутствуют отдельные поля связи с заявителями и даты последней проверки, у обязательства — явная ссылка на дело. Эти сведения нужно сохранять в рабочих пояснениях и исходных документах. Изменение схемы требует отдельной доработки.
- Напоминания, фоновое чтение почты и регулярные обновления требуют доступного инструмента автоматизации и отдельной настройки. Календарь в обзоре показывает даты по предоставленным материалам.
- Справочники задают порядок проверки. Применимые нормы, полномочия, сроки и каналы подачи нужно уточнять по актуальным первичным источникам для конкретного дела.
- Отправка обращений, публикация материалов и контакты с участниками выполняются в пределах явного поручения пользователя и доступных инструментов.

## Проверка пакета

Для машинных проверок нужны Python 3 и библиотека `jsonschema`. Выполняйте команды из корня пакета в выбранном Python-окружении.

```sh
python -m pip install jsonschema
python scripts/validate_package.py
python -m unittest discover -s scripts -v
```

Для проверки собственного JSON-реестра передайте путь к файлу.

```sh
python scripts/validate_package.py --case /path/to/registry.json
```

В пакете 18 автоматических тестов и 43 определения поведенческих сценариев. Валидатор проверяет ссылки, схему, даты и часть связей между записями. Поведенческие сценарии оценивают отдельно по [рубрике](evals/rubric.md). Полезность в длительной работе со многими делами требует последовательных прогонов с новыми документами и сохранением состояния.
