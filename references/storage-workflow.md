# Сохранение и продолжение работы

Применяй при ведении нескольких дел, обработке новых ответов и продолжении работы в другом чате. Рабочее состояние хранится в выбранном пользователем закрытом пространстве. Полный набор реестров служит источником для обзора и календаря.

## Найти рабочее состояние

1. Используй уже указанный файл или хранилище. При первом обращении уточни место, если его нельзя определить из контекста. Для локальной работы предложи отдельную рабочую папку вне публичного репозитория скилла.
2. Для файлового режима используй один файл портфеля. В нём находятся версия формата 1.0, номер ревизии и массив registries с полными реестрами формата 0.4 или 0.5. Индекс строится из этих же записей командой status.
3. Прочитай портфель и необходимые исходные документы перед изменениями. Сохрани полученный SHA-256 портфеля для проверки при записи. Путь и ревизию укажи в первом обзоре и при передаче работы.
4. Каждому независимому реестру назначь устойчивый уникальный campaign.id. Имя поля сохраняет совместимость формата. У шаблона замени campaign-draft, например идентификатором с UUID. При добавлении новых материалов сохраняй существующие ID.

Для просмотра индекса и проверки файла из корня пакета выполни команду с фактическим путём выбранного хранилища.

```sh
python scripts/portfolio_store.py status --workspace /private/workspace/portfolio.json
```

У отсутствующего файла команда возвращает sha256 со значением missing и ревизию 0. Это исходное состояние для первой записи. В существующем файле проверяются все реестры и уникальность их ID. Для полного разбора прочитай сам файл и относящиеся документы. Индекс содержит сокращённые карточки.

## Собрать обращения впервые

1. Определи охват по доступным папкам, переписке и списку пользователя. Для нового портфеля используй `assets/portfolio-empty.json`. Храни рабочую копию и документы отдельно от публичного репозитория. Для уже существующего портфеля начни с его актуальной ревизии.
2. Заполни рабочую копию `assets/intake-template.md`. Сначала составь список заявленных дел, включая дела без документов. Отметь, что известно со слов пользователя, и какие исходные обращения, подтверждения отправки, регистрации, ответы или приложения ещё нужны.
3. До изменения реестра внеси в журнал каждый входящий файл со статусом «ожидает разбора». Сопоставляй файлы по реквизитам и содержанию. Личное обращение, коллективное обращение и кампания могут сосуществовать в одном портфеле. Связывай самостоятельные дела общей кампанией, когда подтверждена общая цель.
4. Обработай однозначные документы по правилам ниже. Для дубля укажи существующий источник. Нечитаемому файлу и неоднозначному ответу оставь отдельную строку с конкретным уточнением. По одному письму проверяй все подтверждённые ветки. Сверяй приложения с тем, что было запрошено и фактически получено.
5. После записи перечитай портфель. Только после сверки укажи «сохранён» и ревизию. При сбое оставь «запись не подтверждена». Журнал ведётся отдельно. Если работа прервалась между записью портфеля и обновлением журнала, сначала сверь отпечатки и связи с сохранёнными источниками и событиями, затем восстанови отметки. При продолжении передай журнал вместе с портфелем.
6. Подведи итог по охвату: какие дела внесены, сколько файлов уже учтено или ждёт уточнения и какие действия приоритетны по подтверждённым срокам. Для неизвестных сроков укажи, какое подтверждение нужно найти.

## Разобрать новые материалы

1. Для каждого нового файла вычисли SHA-256 исходных байтов. Сопоставь его с content_sha256 источников. При совпадении используй существующий source.id. Смена имени файла сохраняет тот же отпечаток.
2. Для сканов, пересохранённых PDF и веб-источников дополнительно сравни отправителя, номер, дату и содержание. Разные байты могут относиться к одному документу. Неизвестный отпечаток оставляй null.
3. Определи реестр, дело и ветку по исходному требованию, адресату, регистрационным реквизитам и предмету ответа. Если выбор неоднозначен, покажи кандидатов и уточни связь до изменения их статусов. Остальные однозначные документы можно обработать отдельно.
4. Один документ может отвечать по нескольким веткам. Используй один источник внутри реестра и отдельные события по затронутым веткам. В событии replied укажи основной документ в reply_source_id и включи его в source_ids вместе с относящимися материалами. Повторный импорт того же ответа в ту же ветку сохраняет существующее событие.
5. Обнови подтверждённые сведения, нужные обязательства и следующие действия. Дату last_verified_on меняй только у проверенного дела. У полученного ответа отдельно оцени исполнение требования. Сохрани существенные сроки остальных веток, обещания и контрольные даты.
6. Исправление факта сопровождай новым событием с источником и пояснением, какое значение уточнено. Отменённую задачу пометь cancelled, прекращённое дело — closed с причиной в событии. Сохрани прежние документы и историю.

```sh
python scripts/portfolio_store.py fingerprint /private/workspace/documents/reply.pdf
```

Источник с одинаковым непустым отпечатком внутри реестра должен иметь один ID. Для версии 0.5 валидатор также проверяет уникальность пары «reply_source_id + ветка» у событий replied. Разные ответы могут ссылаться на одно исходное обращение как на дополнительный источник. Семантическое сопоставление документов выполняет помощник по содержимому.

## Сохранить обновление

Подготовь отдельный файл с полным обновлённым реестром и прежним campaign.id. Проверь изменения по каждому затронутому делу. Команда save обновляет только этот реестр в портфеле, остальные сохраняет как есть.

```sh
python scripts/portfolio_store.py save --workspace /private/workspace/portfolio.json --registry /private/workspace/candidate.json --expected-sha256 HASH_FROM_STATUS
```

Для первой записи подставь missing. Для последующих используй SHA-256, полученный при чтении текущего состояния. После сохранения прочитай возвращённую ревизию и выполни status. Сверь затронутые дела, события и даты. Сообщи путь, ревизию, изменения и оставшиеся неопределённости.

Если файл успел измениться, заново прочитай состояние и согласуй изменения с новыми данными. Повторное сохранение идентичного реестра возвращает changed=false и сохраняет прежнюю ревизию. Команда отклоняет обновление с исчезнувшими записями из любой коллекции. Полные старые версии сохраняются в каталоге .history рядом с портфелем.

Команда блокирует одновременную запись другим экземпляром помощника и заменяет файл после подготовки полного содержимого. Внешние редакторы должны соблюдать ту же блокировку или работать последовательно. После аварийного завершения может остаться файл .lock. Перед его удалением проверь, что записывающий процесс завершён, и сохрани текущее состояние. Автоматическое снятие чужой блокировки запрещено.

При ошибке записи сначала проверь текущий файл командой status. Для отката выбери нужную резервную копию, проверь её той же командой и согласуй восстановление всей ревизии. Сохрани текущую версию перед восстановлением. Резервные копии содержат рабочие данные и требуют такого же режима доступа.

## Продолжить в другом чате

Передай путь к портфелю или сам актуальный файл, его ревизию, место исходных документов и перечень нерешённых уточнений. Начни с status и чтения реестров. Дату нового обзора укажи отдельно от даты проверки каждого дела. Восстанови ближайшие действия из сохранённых записей.

Если среда поддерживает только вложения или документы, выдай полный обновлённый артефакт, укажи его версию и изменения. Попроси использовать его при продолжении. О сохранении в хранилище сообщай после подтверждённой записи. Для файлового помощника нужны Python 3 и jsonschema.
